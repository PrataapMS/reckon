# ADR-0009: Phase 2 World Pulse — world questions, windows, ladders, news and Web Push

**Status:** Accepted, 2026-10-06. Refines spec §3.1–§3.6 for the Phase 2 build. Closes the roadmap's open decision on default RSS feeds.

## Context
The Phase 1 engine is built around places: threshold criteria with coordinates, a forecaster input bundle of weather data, and one generation run per location. Phase 2 adds questions about money, tech, space and the news, which are about no place, and checking the sources live (2026-10-05) showed several spec assumptions do not hold:

1. **Base rates.** An M6+ earthquake happens in about 90% of weeks, and GitHub's status page lists an incident in 10 of 10 weeks. Questions near 100% teach nothing, and the spec's own rule for informative questions (§3.2) is a base rate in [0.25, 0.75]. Kp ≥ 5 within 3 days was 22% over the last six months; a 2× news surge is rarer still.
2. **History depth.** Statuspage returns only its latest 50 incidents, and GitHub's releases endpoint returns 100 per page. For busy services and repos that covers weeks, not the 52 windows §3.3 asks for. NOAA SWPC publishes only 7 days of observed Kp. GDELT searches about 3 months back.
3. **Windows and lock.** "This week" and "Friday vs Monday" have to start after the lock (a database check enforces `lock_at <= window_start`), and the window must not depend on when generation happened to run, or a retry would create a second question.
4. **Licences.** Ars Technica's terms forbid automated caching (and grounding an LLM on its content); The Hindu's forbid caching.

## Decision
1. **World questions are a second template family** (`WorldTemplate`, `packages/core/src/domain/world-templates.ts`), generated once per user per template per day by a `generate.world` work item, with `location_id` null and `meta.scope = 'world'`. A template lists the data it needs; the use case fetches each need through its port and saves it as evidence; the template then derives, for each question, the outcome of every comparable past window. `history.rate@1` (the share of those windows where it happened, from 8 up to 52 windows) and `persistence@1` (the last window's outcome, 0.7 / 0.3) are generic over that history.
2. **Adaptive ladders, as for weather** (spec §3.2): quakes M6 / 6.5 / 7; Kp 4 / 5 / 6; incident impact any / minor / major / critical; news surge 1.1 / 1.25 / 1.5 / 2 / 3 × the 30-day median. The rung nearest a 50% recent base rate within [0.25, 0.75] wins, ties to the more severe rung; with none, the question is skipped that day. Watched repos and status pages are asked only when their own base rate is in range (budget 3 repos and 2 services a week). The template IDs from the spec are kept (`world.quake_m6_week` may ask about M6.5+).
3. **Only fully covered windows count.** If a listing returned a full page (`complete = false`), windows older than its oldest entry are left out of the history, and a resolver that cannot see back to a window's start returns "missing" (retried, then annulled at 72 h, never guessed).
4. **Deterministic windows.**
   - Weekly questions (quakes, releases, incidents) are generated on the user's Monday and run from Monday's brief time to the end of Sunday, local; their target date is Sunday, so they appear in Monday evening's Reveal. Horizon is 6 days, not the spec's 7. A generation after the brief time skips the week.
   - `fx.usdinr_week` compares the ECB reference rates for Monday and Friday (`compare` criteria); the window runs from Monday 12:00 UTC (before the ~14:10 CET fixing) to Friday 16:00 UTC. A missing fixing (an ECB holiday) annuls the question.
   - `space.kp_storm_3d` covers the 72 hours from the first 3-hour UT slot after the brief, judged by NOAA SWPC's estimated planetary Kp (the window needs 20 of its 24 slots). Weekly UTC clusters keep overlapping daily windows from counting as independent.
   - `news.topic_surge` asks, for one topic a day in rotation, whether tomorrow's UTC-day GDELT article count exceeds the multiplier × the median of the last 30 complete days. The whole-article threshold is frozen in the criteria at creation.
   - Each world question carries a `slot` key; generation never creates a second question for the same template, target date and slot.
5. **Kp history comes from GFZ Potsdam** (the definitive Kp series, CC BY 4.0, credited in the footer); resolution uses NOAA SWPC as the spec says. The two differ slightly; only SWPC judges.
6. **NOAA's own storm probabilities are a scored forecaster**, `provider.swpc@1`. SWPC's daily categories (Active, Minor, Moderate, Strong-Extreme) are treated as separate, so P(Kp ≥ t on a day) is the sum of the categories at or above t; days are combined over the window as independent, weighted by overlap, and the forecast must cover half the window.
7. **Reference forecaster per question.** Skill scores compare with `climatology@1` for weather and air and with `history.rate@1` for world questions (`REFERENCE_FORECASTERS`). Both carry the "baseline" trust label. World templates default to `history.rate@1` as champion (spec §3.3 "history.rate (events)").
8. **News pipeline storage.** Headlines go to a mutable `news_items` table (canonical URL unique, title SimHash, tags) and expire after 90 days. When one is first linked to a question it is copied into the append-only `evidence` ledger (kind `news`, SHA-256 of what is shown) and lives on. Tagging is deterministic keyword rules: per world template, per watched repo (with a release word) and service (with an outage word), and per topic. Linking is limited to 8 headlines per question, published before its window closes, ranked by a relevance score. Tagging runs inline in the `news` job; optional LLM tagging (Phase 4) would become a queued step.
9. **Fetch budget.** Feeds and Hacker News (Algolia front page, one call) are polled at most every 50 minutes with ETag / Last-Modified. GDELT allows one request per 5 seconds, so each `news` run refreshes only the 2 stalest searches, at most every 3 hours each. The GDELT client keeps the 5-second gap in-process and allows a 12-second timeout.
10. **Default feeds** (closes the open decision): BBC News World and Technology, NASA news releases and The Verge, displayed as headline, source, time, link and a snippet of at most 280 characters, always linking to the publisher. Ars Technica and The Hindu are excluded on their terms. Topics: India economy, AI, Google, Apple, Microsoft and Nvidia, plus the primary place's name when it is a real place (not "Home" or "Work"). Removing a topic disables it, so defaults are seeded once.
11. **Web Push is the fallback channel.** The brief and reveal go to Telegram when a chat is linked, otherwise to every Web Push subscription of the user (VAPID via the `web-push` library); a 404/410 from the push service removes the subscription. Without VAPID keys the channel does not exist.
12. **Scoreboard v1.** `/scoreboard` shows mean Brier per template and forecaster with the bootstrap trust label; `/scoreboard/calibration` shows a reliability diagram for the probabilities shown to the user (or one forecaster): 5 bins until 500 forecasts, then 10, with Wilson intervals and ECE. The "days resolved" progress counts place clusters only.

## Consequences
- 11 templates are active (5 place, 6 world): 2 world questions a day, plus up to 7 on Mondays.
- Weekly templates need 30 resolved weeks for a trust label, so their labels arrive months after weather's. That is honest, not a bug.
- Short source histories make some early base rates noisy; the forecaster's rationale always states how many windows it used.
- Changing any window, ladder or mapping is a new template or forecaster version, so existing track records stay comparable.
- GDELT could not be reached from the build sandbox (HTTP 429 and timeouts); its adapter was built from the documented formats with synthetic fixtures, which must be re-recorded from a normal network before relying on `news.topic_surge`.
