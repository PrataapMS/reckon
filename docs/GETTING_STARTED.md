# Getting started

From zip to a running Reckon in about 15 minutes locally, and about 30 minutes to a live deployment.

## 1. Prerequisites

- Node.js 24 (`nvm use` reads `.nvmrc`)
- pnpm 9: `corepack enable` (or `npm i -g pnpm@9`)
- Docker (for local Postgres), or a free Neon project
- Git

## 2. Run it locally

```bash
unzip reckon.zip && cd reckon
git init && git add -A && git commit -m "chore: Reckon Phase 0 scaffold"
pnpm install
cp .env.example .env            # defaults work for local Docker
pnpm verify                     # lint, typecheck, architecture rules, unit tests, build
```

Start the database, migrate and seed:

```bash
pnpm db:up                                       # Postgres 16 on localhost:5432
export $(grep -v '^#' .env | xargs)              # load .env into this shell
pnpm db:migrate && pnpm db:seed
pnpm test:integration                            # proves the ledger rules in the database
```

Run the app:

```bash
pnpm dev:api      # terminal 1: http://localhost:8787/api/v1/health
pnpm dev:web      # terminal 2: http://localhost:5173
```

Open http://localhost:5173. Without a passphrase configured, Reckon shows the Phase 0 live preview for the default city. With one (next section), you sign in, onboard in three steps (place, Telegram or skip, times) and land on your brief. Every number is labelled "learning" because nothing has been scored yet: that is correct.

Optional checks:

```bash
pnpm test:contracts     # hits the real Open-Meteo API
curl localhost:8787/api/v1/brief/preview?lat=28.61&lon=77.21&tz=Asia/Kolkata
```

### Set a passphrase (enables sign-in and the daily brief)

```bash
pnpm --filter @reckon/api hash-passphrase "choose a long passphrase"
# paste the output into PASSPHRASE_HASH in .env; set SESSION_SECRET with: openssl rand -base64 48
```

### Run the daily loop locally

Netlify runs the jobs on a schedule; locally you run them by hand. Each one is idempotent and due-based, so running one twice does nothing extra.

```bash
pnpm job generate   # writes questions for each place and collects every forecaster's probability (due from 2 h before the brief time)
pnpm job tick       # locks due questions, resolves finished days (6 h after midnight), sends the outbox
pnpm job brief      # builds and sends the morning brief (needs Telegram)
pnpm job reveal     # resolves what is due and sends the reveal
pnpm job news       # fetches feeds, Hacker News and GDELT; tags headlines and links them to world questions
```

World Pulse questions (money, tech, space, news) are generated by the same `generate` and `tick` runs, once per user: daily for Kp and news coverage, and on Mondays for the weekly ones (FX, quakes, releases, incidents).

Raw evidence is written to `.data/evidence` locally (Netlify Blobs in production).

### Tests

```bash
pnpm test                 # unit + use-case tests (in-memory ledger, fake Open-Meteo)
pnpm test:integration     # the same daily loop against Postgres, in a throwaway database
pnpm test:contracts       # every live source (Open-Meteo, Frankfurter, USGS, GFZ, NOAA, GitHub, Statuspage, Hacker News, RSS, GDELT)
pnpm --filter @reckon/e2e exec playwright install chromium   # once
pnpm test:e2e             # onboarding → brief → reveal, World pulse, scoreboard, topics, on a fake clock, light and dark, axe-core
```

## 3. Deploy (Neon + Netlify, both free)

**Neon**
1. Create a free project at neon.com in region **AWS us-east-2 (Ohio)**.
2. Copy the **pooled** connection string (it contains `-pooler` and `sslmode=require`).
3. From your machine: `DATABASE_URL="<neon url>" pnpm db:migrate && DATABASE_URL="<neon url>" pnpm db:seed`.
4. Optional least privilege: in Neon's SQL editor run `grant reckon_app to <your_login_role>;`.

**GitHub**
1. Push the repo (create `main` and `dev` branches).
2. Add repository secrets: `DATABASE_URL` (Neon), `CONTACT_EMAIL`, `BACKUP_AGE_RECIPIENT` (from `age-keygen`; keep the private key offline).

**Netlify**
1. "Add new site" → import the GitHub repo. `netlify.toml` already sets the build command, publish folder and functions folder.
2. Site settings → Environment variables: `DATABASE_URL`, `SESSION_SECRET`, `PASSPHRASE_HASH`, `DEFAULT_LAT`, `DEFAULT_LON`, `DEFAULT_TZ`, `CONTACT_EMAIL`, and for Telegram `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET`. Evidence goes to Netlify Blobs automatically; `APP_URL` defaults to Netlify's `URL`. Optional: `GITHUB_TOKEN` (a token with no scopes; lifts GitHub's 60 requests/hour limit) and, for Web Push, `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` from `pnpm push:keys`.
   After pulling Phase 2, run `DATABASE_URL="<neon url>" pnpm db:migrate && DATABASE_URL="<neon url>" pnpm db:seed` again (migration `0002_phase2.sql` adds topics, headlines and push subscriptions).
3. Deploy. Then open `https://<site>.netlify.app/api/v1/health`.
4. Functions → `tick` → "Run now" once; `/health` should list a `tick` with status `ok`. That is Phase 0's acceptance check.

**Telegram (optional, about 5 minutes)**
1. In Telegram, message [@BotFather](https://t.me/BotFather): `/newbot`, pick a name and a username ending in `bot`. Copy the token.
2. Set `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (without the @) and `TELEGRAM_WEBHOOK_SECRET` (`openssl rand -hex 24`) in Netlify and redeploy.
3. Point the bot at your site: `TELEGRAM_BOT_TOKEN=… TELEGRAM_WEBHOOK_SECRET=… pnpm telegram:webhook https://<site>.netlify.app`
4. In Reckon → Settings → "Link Telegram", open the link and tap Start. The bot replies "Linked".

**Web Push (optional; the fallback when Telegram is not linked)**
1. `pnpm push:keys`, then set both values in Netlify and redeploy.
2. In Reckon → Settings → "Notifications on this device" → "Turn on for this device". On iPhone, add Reckon to the Home Screen first.

**Phase 1 acceptance (after deploying):** for 7 days, check that the brief arrives by your brief time with at least 4 items, that `/api/v1/health` shows `generate`, `brief`, `reveal` and `tick` runs with status `ok`, and that each revealed question's detail page offers its raw evidence.

**Phase 2 acceptance (after deploying):** `/api/v1/health` also lists `news` runs with status `ok`; within a few weeks the Scoreboard shows 100+ resolved questions, at least half of the world and tech questions show headlines under "Why we believe this", and any failed nightly contract run has an open GitHub issue.

**Working agreement:** develop on `dev` (branch deploys are free); merge to `main` about once a week, because each production deploy costs 15 of the 300 monthly free credits.

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `DATABASE_URL is not set` | `export $(grep -v '^#' .env | xargs)` or pass it inline. |
| Brief says "could not load" | Is `pnpm dev:api` running on 8787? Vite proxies `/api` to it. |
| `/health` shows `database: unavailable` | Check the URL; on Neon use the pooled string with `sslmode=require`. |
| Netlify build fails on functions | Make sure `netlify.toml` still lists `external_node_modules = ["pg-native"]`. |
| Today says "No claims are locked for today yet" | Expected on day one: questions are written for tomorrow onwards. Run `pnpm job generate` again tomorrow morning, or wait for the schedule. |
| Adaptive questions (rain amount, high temperature, AQI level) are missing | No rung of the threshold ladder has a base rate between 25% and 75% at this place and season, so the template skips the day. |
| The bot never replies | Re-run `pnpm telegram:webhook …`; the secret in the URL and in Netlify must match. Only private chats are answered. |
